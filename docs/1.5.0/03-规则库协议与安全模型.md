# CCB v1.5.0 规则库协议与安全模型

## 1. 文件组成

### Manifest

```json
{
  "schemaVersion": 1,
  "registryVersion": "1.0.0",
  "minimumAppVersion": "1.5.0",
  "publishedAt": "2026-07-12T00:00:00.000Z",
  "bundleUrl": "https://dev.niansir.com/software/ccb/registry/1.0.0.json",
  "bundleSha256": "<64 lowercase hex characters>",
  "bundleSize": 12345,
  "releaseNotes": {
    "zh-CN": "更新工具适配规则",
    "en-US": "Update tool adapter rules"
  }
}
```

Manifest 只用于版本提示，不能包含 tool rules。应用启动检查只获取 manifest，不获取 `bundleUrl` 内容。

### Bundle

```json
{
  "schemaVersion": 1,
  "registryVersion": "1.0.0",
  "minimumAppVersion": "1.5.0",
  "tools": []
}
```

## 2. Tool schema 摘要

```json
{
  "toolId": "claude-code",
  "definitionVersion": "1.0.0",
  "displayName": { "zh-CN": "Claude Code", "en-US": "Claude Code" },
  "platforms": ["WINDOWS", "MACOS", "LINUX"],
  "detectors": [
    { "type": "COMMAND_EXISTS", "command": "claude" },
    { "type": "PATH_EXISTS", "path": "${HOME}/.claude" }
  ],
  "artifacts": [
    {
      "artifactId": "user-settings",
      "format": "JSON",
      "scope": "USER",
      "paths": {
        "WINDOWS": ["${HOME}/.claude/settings.json"],
        "MACOS": ["${HOME}/.claude/settings.json"],
        "LINUX": ["${HOME}/.claude/settings.json"]
      },
      "capabilities": ["DISCOVER", "READ", "VALIDATE", "EDIT", "BACKUP", "RESTORE"],
      "handler": "JSON_FILE_V1"
    }
  ]
}
```

## 3. Validation limits

- Manifest max 50 KB；bundle max 2 MB。
- tools max 100；每 tool artifacts max 50；detectors max 10。
- string max 4096 chars；localized text max 2048 chars。
- JSON nesting max 20；总节点数 max 50,000。
- identifiers 必须匹配 `^[a-z0-9]+(?:-[a-z0-9]+)*$`。
- SemVer 必须 strict，无 leading zero 或 arbitrary suffix。
- bundle URL 必须 HTTPS 且 origin 命中 application-pinned allowlist。
- SHA-256 必须在 parse 前基于 raw bytes 验证。
- 禁止 unknown top-level security-sensitive fields；schema 默认 `additionalProperties: false` 语义。

## 4. Update state machine

```text
IDLE
  -> CHECKING_MANIFEST
  -> UPDATE_AVAILABLE | UP_TO_DATE | CHECK_FAILED

UPDATE_AVAILABLE --user confirms--> DOWNLOADING
  -> VERIFYING_HASH
  -> VALIDATING_SCHEMA
  -> CHECKING_COMPATIBILITY
  -> STAGING
  -> INSTALLED
  -> ROLLED_BACK (only explicit user action or load failure)
```

应用不得在 `UPDATE_AVAILABLE` 自动跨到 `DOWNLOADING`。

## 5. Storage layout

```text
~/.ccb/registry/
├── manifest-state.json
├── installed.json
├── installed.meta.json
├── last-known-good.json
└── staging/
```

所有 JSON 使用 UTF-8、atomic temp+rename。成功 load 新 installed bundle 后才替换 last-known-good。启动加载失败则回退 last-known-good 并记录 notification，不删除故障文件以便诊断。

## 6. Threat model

| Threat | Control |
| --- | --- |
| Registry server compromised | SHA-256 integrity + future signature slot；无 executable payload；capability allowlist |
| MITM / redirect | HTTPS + pinned origins + redirect origin revalidation |
| Path traversal | restricted variables + canonical path boundary checks |
| Remote code execution | no scripts/commands in artifacts；detector command limited to command name |
| Schema bomb / memory exhaustion | byte, depth, node, array and string limits |
| Downgrade attack | reject lower version except explicit local rollback |
| Partial write / power loss | staging + atomic rename + last-known-good |
| Malicious remote `$ref` | remote refs forbidden |
| UI spoofing | display registry source, version, hash and update notes |

## 7. Signature evolution

SHA-256 只能证明下载内容与 manifest 一致，不能在 manifest server 被攻陷时证明 publisher identity。v1.5.0 protocol 预留 `signatureAlgorithm`、`keyId`、`signature` 字段，但 production remote registry 上线前建议加入 Ed25519 detached signature，并将 public key 固定在 application binary。未实现签名时，remote registry 应标记为 preview/beta，默认只启用 embedded registry。
