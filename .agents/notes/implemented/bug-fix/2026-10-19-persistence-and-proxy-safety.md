# Agent Note: 配置写入与代理失败边界

Status: implemented
Scope: src/main/**, src/renderer/src/store/settings-store.ts, tests/unit/**
Last-verified: 2026-10-25


## Problem

固定临时文件在并发写入时损坏 JSON，配置集忽略 valid:false，旧配置写入和设置错误反馈会损失数据或让用户误判保存结果。上游响应正文与客户端取消没有完整的结束边界。

## Decision

沿用所有配置路径和落盘格式。原子写使用随机独占临时文件、文件同步和同路径写入队列，失败只清理自己的临时文件。配置集检查全部校验结果后再写，首次创建只跳过不存在文件的备份。旧配置与设置复用同一写入工具，备份失败阻止覆盖，UI 仅在主进程报告成功后清除草稿标记。代理通过 AbortSignal 传播取消，普通响应设置总时限，SSE 保持长流并回收断开的连接，不自动重试 POST。

托管设置只在文件不存在时从空对象创建；损坏 JSON、非对象或读取错误均保留原文件并失败。备份目录不可读不被视为没有备份。启用/重启写入失败及停止/禁用恢复失败均向调用方报告；代理已经启动或停止时明确说明，不伪装成回滚完成。UI 重启按钮实际调用并检查 IPC；切换服务商检查返回值，完成后只刷新状态，不重复重启。

端口占用以实际 listen 的结果为准，不用可能复用旧连接的健康请求推断。停止时给请求 3 秒结束，随后关闭剩余 HTTP 连接，等待 server 真正关闭后才继续；关闭错误继续传回调用方。断开的转发连接沿用既有 AbortSignal 取消，不自动重试。

## Alternatives considered

- 数据库与跨文件事务可提供更强一致性，但会改变存储协议；本轮保留逐文件原子替换和既有备份恢复语义。
- 只随机化临时文件名可避免互删，但不能保证同路径写入顺序；需要轻量队列。
- 对付费请求自动重试可隐藏网络错误，但结果未知时可能重复执行，因此明确失败并保留核对机会。

## Verification

并发保存无损坏；无效配置集零写入；备份或原子替换失败保留原内容；失败设置保存保留草稿；缺失文件可创建；正文超时和客户端取消均回收上游；现有兼容测试、完整类型检查、lint 和双构建通过。

## Consequences

逐文件写入仍不是多文件事务。队列限于单进程；应用已有单实例约束，其他 CLI 同时修改配置不属于队列锁定范围。回归只操作临时用户目录。历史决策检索未发现同主题活跃 Note；保留 ARCHITECTURE 与 v1.5.0 安全/迁移协议的路径及信任边界。

## Test evidence

故障注入覆盖并发写、rename 失败保留原文件、备份失败阻止覆盖、配置集校验失败不写入、设置失败不提交内存及 UI、缺失目录创建、正文卡住超时与下游断连取消。最新完整回归和验证边界见 SECURITY_AUDIT_REPORT.md。

1.5.1 收尾新增 12 项托管故障测试，先复现后修复；真实生产构建复现并修复重启按钮未调用 IPC、停止后健康请求误报端口占用、持续连接未释放的问题。最终完整回归 46 files / 351 tests（含两项新增真实监控测试），无跳过；实际界面验证重启成功、损坏 JSON 显示错误且原文不变，以及禁用后准确恢复原设置。业务 fixture 在外部证据目录保存，使用独立用户目录，不连接付费提供商。
